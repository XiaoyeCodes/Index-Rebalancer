# 行情自动核实与恢复

自动更新会先核对证券、币种、交易日期和价格口径，再处理来源缺失或报价冲突。全部行情、复权因子和独立计算检查通过后才发布。任何未解决的关键校验失败都保留上一份已发布数据。

## 自动处理规则

| 情况 | 处理方式 |
| --- | --- |
| Yahoo 与通常的第二来源一致 | 采用已核实的市场价格，无须生成修正记录。 |
| 第二来源尚缺最新日期或暂时连接失败 | 查询第三来源；与主源同日收盘一致后使用替代核验，并注明实际来源。 |
| 主源日线缺失，包括完全没有该日记录 | 仅在两家非主源的同日 OHLC 一致后补齐；未知成交量保持为空。补入的时间戳仅为交易日期锚点，并明确标记。 |
| 主源价格错误或 OHLC 不完整 | 两家非主源的完整同日 OHLC 一致后才替换对应字段，同时维护复权值。 |
| 第二来源与主源冲突，但第三来源支持主源 | 保留主源，将被拒绝的对照报价和核实依据逐日存档。 |
| 三方无法一致、只有一家可用或核实结果存在歧义 | 刷新来源并重试；仍不能核实时停止发布。 |

美股使用 Yahoo、Nasdaq、腾讯财经；A 股与港股使用 Yahoo、腾讯财经、东方财富。东方财富明确请求未复权日线。腾讯的交易时价格按已经生效、且由主源报告的拆股事件换算到相同股数单位；未来公告拆股不提前应用，不根据价格大幅波动猜测拆股。

替换整条日线需要两家非主源对开、高、低、收分别一致。美股容差为 0.011 美元，沪深/港股报价容差为 0.00051 当地货币，上证指数为 0.006；沿用已有核验精度，不因来源故障放宽。容差交叠造成的歧义不被当作可靠多数。

## 证据与重复运行

自动记录保存于 [automatic-quote-resolutions.json](../app/data/automatic-quote-resolutions.json)，包括证券与币种、具体日期、原始字段、采用字段、各来源地址及响应摘要、核实时间和拆股口径。原 [quote-repairs.json](../app/data/quote-repairs.json) 中已核实的缺失日线会迁移一次，继续保留原来源和时间。

重新下载后会重放这些记录，避免相同错误再次阻断更新。供应商自行修复时接受正确值；出现第三种新报价时重新核实，保存旧记录作为历史，而非直接借用旧结论。重复运行不重复调整复权值。经本程序修正过的值不会冒充 Yahoo 的独立原始报价来投票。

人工复核的 [history-resolutions.json](../app/data/history-resolutions.json) 保持独立，自动档案不能覆盖同一日期的人工结论；人工复核条目发生无法匹配的新变化时仍要求复核。

## 长期历史核验

Nasdaq 的约十年历史仍逐日核对。新增、未解释的历史差异会查询腾讯同日价格，统一拆股口径后按相同规则核实。核实并应用修正后，会重新生成周线和重做核验。

如果长期历史接口只是尚未发布最新交易日，而最新收盘已由近期核验中的两家独立来源确认，可以继续审核接口已有的历史区间，并明确记录历史实际截至日和最新收盘的替代来源。缺口不得超出近期已核实日期的覆盖范围，也不能用错误证券、旧日期或重复来源充当佐证。

## 重试与发布

1. 网络或 JSON 错误：等待 2 秒、6 秒重试，最多三次请求。
2. 尚未核实的近期缺失/冲突：重新查询来源，等待 10 秒、30 秒，最多三轮。
3. 整轮更新仍失败：私有调度任务等待 60 秒、180 秒，再各完整重跑一次，最多三次完整更新。每次重新尝试均从该任务的临时工作目录获取当前主分支，避免推送失败后一直停留在过时版本。
4. 任一轮成功即停止重试，发布核验通过的数据；全部尝试失败才让任务失败并沿用 GitHub 的失败通知。任务上限为 30 分钟。

自动证据与行情、计算报告、页面在同一个发布事务中保存；生成或独立复算失败时一并回滚。网站原有的实时过期提示会继续显示“待更新”，不会把旧交易日伪装成新数据。

## 验证与边界

故障测试覆盖迟到数据、TLS 失败、缺失整条日线、错误 OHLC、第三方核实、重复运行、档案修订、拆股、除息、假多数、错误证券/币种/日期、人工记录冲突及重试预算。另有使用真实备用报价的隔离演练；模拟缺陷和模拟证据留在临时目录，不会发布。

复权检查重建供应商报告的现金分红因子，不额外声称独立核实了全部公司行动事件。所有来源长期不可用、持续冲突、身份/币种变化、人工结论失配或独立计算失败时仍保留失败提醒。GitHub 调度、账户额度和权限故障也可能中断运行；系统无法保证任何外部故障都自动消失。
