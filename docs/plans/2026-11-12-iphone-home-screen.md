# iPhone 主屏幕版

用户选择先交付无需开发者账号、可添加到 iPhone 主屏幕的版本，并要求遵循手机操作习惯。

## 方案与取舍

| 方案 | 功能复用与安装 | 维护成本 | 当前决定 |
| --- | --- | --- | --- |
| 主屏幕 Web App | 复用现有账号、定投算法、云账本；Safari 手动添加即可 | 维护同一套应用，随网站发布更新 | 采用，符合用户安装偏好 |
| SwiftUI / WKWebView 工程 | 能接入原生能力；签名和分发需要 Apple 工具链 | 增加 iOS 工程、签名及分发维护 | 后续有原生能力需求时再评估 |
| SwiftUI 全量重写 | 可完全定制原生交互 | 算法、数据及 UI 双份维护和验证 | 当前成本不匹配需求 |

依据：[WebKit 主屏幕 Web App 与 manifest 说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)、[Apple WKWebView](https://developer.apple.com/documentation/webkit/wkwebview)、[App Review Guidelines 4.2](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality)。用户选择主屏幕版，因此不依赖 TestFlight 或商店审核。

## 交互与模块

- 登录页与应用都声明 manifest、主屏幕图标、独立窗口和安全区域。
- 手机底部放「本月、记录、标的、模型、更多」五个入口；更多弹出菜单提供 AI 助手、历史回测和设置。桌面保留原导航。
- 输入字号至少 16px，主要触控区域至少 44px，保留浏览器缩放。内容和弹窗避开刘海与底部手势区；编辑输入时隐藏底部导航，减少键盘遮挡。
- 登录页及设置提供 Safari「分享 → 添加到主屏幕」步骤；独立窗口中显示已启用状态。首次从主屏幕进入可能需要重新登录，使用同一访问密码同步云账本。
- 继续使用现有加密账号、按版本缓存的加密应用和网络同步，不增加另一套数据源或缓存明文投资信息。

## 范围与验证

此版保持联网使用，不引入 Service Worker、离线行情或通知权限。已有应用加密缓存加快同版本启动；新版本沿用网站发布流程。弱网失败继续走现有错误与同步重试提示。

在 WebKit 和 Chromium 的手机视口验证登录、底部导航、更多菜单、弹窗、键盘输入、安全区域、表格滚动和图表操作；检查 manifest 子路径、图标尺寸、构建发布资源和现有测试。真实 iPhone 上的「添加到主屏幕」确认步骤需用户在设备上操作，不能用桌面模拟器冒充实机安装成功。

验证中发现 WebKit 未稳定复用普通 HTTP 缓存，因此应用密文另存到 IndexedDB，使用绝对版本地址作为键，最多保留两个版本；命中后仍须通过 AES-GCM 解密认证才能打开。缓存不可用时正常联网登录，损坏时重新下载一次，不保存明文页面或密码。在 1 MB/s 加 100ms 延迟的受控 WebKit 测试中，再次自动登录约 0.4 秒、应用包网络下载为零；新版下载、退出和错误密码场景均通过。两种引擎均验证了取消定投不改持仓、确认后记账并锁定本期的流程。
