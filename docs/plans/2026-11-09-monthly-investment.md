# Monthly investment and bonus purchase implementation plan

**Goal:** 发薪后按月买入并确认持仓，每月只记一次常规定投，同时允许独立的奖金加仓。

**Architecture:** 在现有前端、买入分配器和 Ledger 账本内区分 monthly / bonus / rebalance 三种操作。日期与去重规则放入无网络依赖的 `app/investment.js`，最终成交仍经过现有持仓锁、快照检查和账本保存。

**Tech Stack:** 原生 JavaScript、HTML、CSS、localStorage、Web Locks、Node test、Python Playwright。

## 需求与假设

- 用户确认：以当前 Index-Rebalancer 为主，按需补充调研。
- 用户要求：每月发薪后的购买清单、成交后更新按钮、本期完成拦截与下次日期、奖金突破入口和输入金额后的自动分配。
- 工作假设：一期指本地自然月；“加仓价格”指本次投入总金额（人民币），汇率与碎股 / 整手沿用已有设置。
- 计划定投日可设置为每月 1–31 日，短月份取最后一天。提醒日期不强制限制本月首次投入。
- monthly / bonus 只用新增资金买入；rebalance 使用模型原有阈值与季度 / 年度检查规则，不叠加月度资金。
- 奖金不改每月预算、不占用下月额度、不完成本月常规定投。
- 输入金额或计算预览不改变真实持仓；手动在券商购买后确认才更新持仓和流水。无实际成交不消耗本月名额。

## 调研与取舍

当前工作区代码事实：`planRebalance()` 将常规投入和卖出再平衡合并；`contributionMonth` 使本月再次投入为零；`nextRebalanceDate()` 对定期模型返回季度 / 年度日期。Ledger 已支持成交、现金流与保存失败回退；`withCurrentHoldings()` 已支持同源标签页锁和过期快照检查。

官方资料：

- [Investor.gov 定投定义](https://www.investor.gov/introduction-investing/investing-basics/glossary/dollar-cost-averaging)：周期性投入新资金，与市场涨跌无关。
- [Investor.gov 资产配置与再平衡指南](https://www.investor.gov/sites/investorgov/files/2019-02/Beginners-Guide-to-Asset-Allocation.pdf)：按日历或偏离检查再平衡，新增资金可以流向低配资产。
- [MDN Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)：锁协调同一来源的多个标签页；不提供跨设备全局锁。

比较：只加“额外金额”按钮无法修正日期与记账混用；独立建立第二套资金及持仓系统会增加对账成本。采用三种操作类型共用现有分配与账本，保留整股限制、低配优先和模型规则。

## 实施步骤

1. 新建 `app/investment.js`：自然月标识、计划日计算、已完成判断、操作去重、真正的再平衡检查日期。旧 `contributionMonth` 及旧定投流水继续识别为已完成，避免升级后再次定投。
2. 修改 `app/src.html` 和 `app/ui.css`：月度定投 / 奖金加仓 / 再平衡入口，金额与定投日输入，已完成弹窗，明确的成交确认按钮。
3. 改造 `planRebalance()`：依操作类型决定资金及是否允许卖出；操作后占比、零钱与成交股数一致。常规与奖金资金分别计算，奖金使用单次 ID。
4. 改造成交确认：快照包含操作类型和金额；确认时重新检查周期与操作 ID；在同次状态写入内保存成交和完成标记。保存失败恢复持仓并保留弹窗重试；切换页面、跨日和其他标签页改动使旧确认失效。
5. 同步持仓解读、复制清单、研究上下文和再平衡日期口径。
6. 构建 `app/heng.html`，验证桌面与手机布局，并更新产品设计书。

## 验收

- 定投：未完成时输入金额得到只买入清单；确认后股数、流水与本期状态一致；刷新和双击不能重复记账。
- 完成拦截：再次点击弹出“本期已经定投，下次定投时间在 …”，可从弹窗进入奖金加仓。
- 日期：独立于再平衡周期；月末、2 月、跨年正确；下个自然月恢复常规定投。
- 奖金：当月已完成仍可输入金额并买入；单次不能重复确认；可明确新建第二笔；不改每月预算或常规定投标记。
- 预算：只买入模式没有卖出、没有负现金；整股与碎股估算符合持仓精度，剩余资金明确列出。
- 兼容：旧的本月完成标记不会清除；旧持仓、流水、自建模板和收藏保留。
- 可靠性：存储失败、过期快照、其他标签页先完成时均不会假报成功或重复追加；跨设备沿用既有共享冲突处理，不声称全局恰好一次。
- 无实际成交不记为本月已完成；空模型、示例持仓与无效金额有明确反馈。

## 交互修订（2026-11-10）

本期完成提示只由“本期已定投，查看下次日期”按钮触发；切换每月定投、刷新或刚记账成功不自动弹出。顶部移除奖金加仓切换项，继续加仓保留在完成弹窗中。弹窗复用再平衡确认的日期卡片布局，显示下次月度定投日期、今天、本期记录和剩余天数，主按钮为“确认，继续加仓”。桌面及 320–390px 手机布局已检查。

继续加仓改为第二个独立弹窗：输入总金额后在弹窗内预览各标的比例、人民币金额、美元参考额、股数与未投入现金；点击“已买入，更新持仓”才共用原有记账流程写入，主页面始终保留每月定投。`verify-bonus-dialog.py` 的 6 组场景通过，覆盖 5 种屏幕宽度、预览 / 取消 / Escape / 输入回车不记账、双击去重、存储失败恢复与重试、模型改变和其他标签页改变后的重算与再次确认；无页面错误。月度流程 11 组浏览器回归及 30 项 Node 测试通过。
