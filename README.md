# Dynamic Rebalancing

**全天候动态再平衡策略。** 每月发薪后打开，告诉你这笔钱该买哪些指数基金、各买多少；有资产偏离目标太多时，也告诉你该卖什么。

*Index fund DCA, rebalanced. Steady by design.*

## 登录

从任意电脑打开 [GitHub Pages 登录页](https://xiaoyecodes.github.io/Index-Rebalancer/)，输入共享访问密码即可使用定投与持仓工具。网页版无需安装软件。

登录默认勾选「保持登录（30 天）」。同一浏览器再次打开或刷新时自动进入，网站更新不影响有效的登录状态；在设置中「退出登录」、清除本站浏览器数据、到期或更换共享密码后需要重新登录。取消勾选只用于本次登录。网页版在当前浏览器的 IndexedDB 中保存不可导出的解锁密钥，不保存明文密码；本地服务使用 HttpOnly Cookie 保存登录会话。

## 网站部署

公开源码仓库通过 GitHub Actions 部署 Pages。发布物包含登录页、加密应用包和助手静态资源。输入共享密码后，浏览器用 Web Crypto 解锁应用。共享密码控制网页入口；项目源码公开。启用共享后，投资账本在浏览器中加密并同步；AI 密钥和 AI 对话仍按浏览器单独保存。

维护者更换共享密码时，将当前密码和新密码分两行通过标准输入交给 `node app/scripts/set-pages-password.mjs`，重新发布生成的访问配置。此操作保留账本加密密钥。已获得旧密钥的设备仍可能访问共享数据；撤销旧设备需要更换工作区密钥并迁移账本。

本地生成部署文件：

```bash
npm ci --prefix assistant
npm run build --prefix assistant
node app/scripts/build.mjs
node app/scripts/publish.mjs
```

## 共享投资账本

公网网页版登录后，在「设置 → 共享账本」查看同步状态、下载先前版本或处理同步操作；本地预览不显示此分区。第一次从有原始记录的设备登录，选择「用本机数据开始共享」。新浏览器会读取同一份持仓、交易记录、定投设置、收藏和自建模型。已有独立记录的设备会先提示备份，再加入共享账本。相互独立的修改自动合并，同一份持仓或同一项设置冲突时需选择要保留的版本，可下载另一版。

Cloudflare Worker 使用一个 SQLite Durable Object，通过版本号检查并串行保存加密账本。网页在可见时约每 5 秒拉取一次，断网修改在恢复连接后重试。只有页面显示「共享账本已同步」表示已完成同步。推送到 `main` 的提交包含 `sync/` 变更时，GitHub Actions 的 [Deploy Cloudflare sync](.github/workflows/deploy-sync.yml) 会发布 Worker。每次发布都会标记 Git 提交并检查网页跨域请求和未登录访问控制。部署令牌保存在仓库 Secret `CLOUDFLARE_API_TOKEN`，账户 ID 保存在仓库变量 `CLOUDFLARE_ACCOUNT_ID`。把 HTTPS 服务的 `/workspace` 地址填入 `app/sync-deployment.json` 后重新发布 Pages。访问凭证的服务端校验值保存在 `sync/access.json`。此文件只包含摘要。

## 投资数据备份、恢复与清空

「设置 → 投资数据」提供备份到 GitHub、从 GitHub 恢复、下载备份文件、导入备份文件，以及清空投资数据。

清空需要再次输入登录密码。默认勾选「清空前先备份到 GitHub」；只有 GitHub 写入、回读以及浏览器解密核验均成功后才继续清空，备份失败不执行清空。可取消勾选直接清空。清空范围包含我的持仓、投资记录、期初成本、历史成交、已确认定投／再平衡记录与重置机会；保留模型、每月预算、计划日及规则。清空与恢复都会同步到共享账本，其他登录设备随之更新。

GitHub 备份保存到私有仓库 `XiaoyeCodes/Index-Rebalancer-Automation` 的 `codex/investment-backups` 分支、`investment-backups/` 目录。持仓和记录在浏览器中用账户密钥 AES-256-GCM 加密后上传；服务器不解密投资内容。备份不包含登录密码、AI 密钥、聊天记录或浏览器登录凭据。服务器端 GitHub 凭证仅保存在 Cloudflare Secret，部署凭证来源为仓库 Secret `INDEX_REBALANCER_BACKUP_TOKEN`；维护者可替换为仅允许备份仓库 Contents 读写的专用凭证。授权过期或撤销时，页面报告备份失败。

从 GitHub 列表或 JSON 文件导入后，先显示持仓标的数、记录数、每月预算和计划日；再次验证密码后整份恢复，避免重复追加成交。支持当前加密备份及旧版下载的 `{state,templates}` 投资账本。加密文件需要使用创建备份的同一工作区登录，保留工作区密钥的密码更换不影响恢复。恢复包括持仓、投资记录、当前模型、本月完成状态、预算、日期和自建模型。若其他页面或设备在操作期间有新数据，需同步后重新核对，不能静默覆盖。

本地服务版本支持密码验证后的清空、下载及导入文件；GitHub 加密备份在公网网页版登录后使用。单份投资账本上限 1 MB，不自动删除历史备份。

## 定投与再平衡

模型的「资金配置方式」分为三种：固定比例定投，每期按目标比例买入，超配也不因此停买；只买不卖，只用新钱优先补低配，超配标的可能少买或不买；允许买卖再平衡，达到阈值或定期规则时卖出超配、买入低配，新增资金可另选固定比例或优先补低配。只有允许买卖时才启用触发规则。自建模型一并保存是否允许卖出与新钱分配方式。

历史回测、净值 K 线、走势对比、市值与累计投入、基准表及持仓解读的历史风险使用同一份当前模型配置。同规则对照与本策略合并显示；只买不卖不生成卖出、调仓标记或买卖换手。回测仍采用复权周线、每月首个交易周投入、允许碎股与固定汇率等值金额；实际定投日、整股限制和上次执行日期仅用于实盘清单，页面会明确说明。

「与基准对比」展示本策略、同额定投标普 500，以及其他三种资金配置方式，共五行；与本策略规则相同的对照自动省略。去重依据规则，不合并仅因四舍五入而数值相同的不同策略。本策略注明当前选择，买卖对照在主标题中区分“新钱补低配／新钱固定比例”；触发方式、阈值与季度／年度频率跟随模型，名称同步更新。当前模型不启用买卖触发时，买卖对照使用模型保留的季度／年度频率做定期再平衡，表下注明。除标普基准外，标的和目标权重保持一致，所有组合使用相同投入、费用与共同历史区间。

净值 K 线悬停显示本策略与标普 500 的当月涨跌幅、收盘净值，以及本策略的月度开高低收。月涨跌使用本月收盘净值相对上月收盘净值的变化，首月相对起始净值 1.00，计入费用并剔除定投现金流影响；移出图表即隐藏，重算模型后更新。

「逐年收益」与「再平衡记录」在固定高度面板内分别分页，最新记录在前，每页数量随面板高度及行高调整；超出一页才显示上一页／下一页、页数和总数量。重新回测回到第一页，翻页互不影响，不重算图表。再平衡记录完整保留，不再仅显示最近 300 条。

本月计划的操作区用两个时间卡片显示「下次定投」和「下次再平衡」，各自的操作按钮放在卡片右侧。未完成当月定投时可点击「定投」，在弹窗输入本次金额，实时查看买入比例、金额、股数和未投入现金；在券商买入后点击「已买入，更新持仓」才写入本期记录。弹窗金额不改变模型设置的每月预算，取消或预览均不记账。

时间卡片左侧显示计划日期和说明。定投按每月计划日和完成记录计算，短月取月末；定期再平衡显示季度 / 年度检查日期，阈值模式显示「达到偏离阈值时」，混合模式注明可提前触发。手动重置会注明已解锁，同时保留常规计划日期；到期未完成的操作显示待办状态。切页、确认操作和日期变化时自动刷新提醒。

触发模型阈值或定期规则、允许卖出且有可成交操作时，「再平衡」按钮可点击；弹窗列出需买入或卖出的标的、金额、股数和占比变化。确认已执行后才更新持仓。两个操作按各自的当月记录独立判断完成，完成或暂不满足条件时，按钮禁用并显示灰色的「本期已定投」或「本期已再平衡」，切页和刷新后保持。

需要提前操作时，在「设置 → 投资操作」点击「重置定投」或「重置再平衡」，二次确认后各解锁一次本期操作；取消或 Escape 不做任何修改。重置不会改变常规的下次定投或定期再平衡日期。设置按钮随即显示「定投已解锁」或「再平衡已解锁」，关闭设置后使用主页对应按钮。取消操作弹窗、切页或刷新会保留机会，确认记账后自动用完并恢复灰色按钮，原有记录和持仓保留。待使用的机会不能叠加，跨月失效。重置再平衡后可提前打开检查弹窗，跳过日期和阈值条件；持仓已接近目标、为空、成交金额不足或设置为只买不卖时，弹窗说明原因并保留机会，实际确认记账仍需允许卖出且有可成交买卖。

示例持仓可以预览，不能记账。请先在「我的持仓」填写真实股数，未持有的填 0。每月预算及再平衡规则仍可在「定投模型」中设置。

## AI 助手

进入「AI 助手」，点击「研究我的定投计划与当前持仓」即可发送当时的持仓和本月清单。普通新对话仅发送问题。回答支持 Markdown、复制原文和 PDF 下载。可在历史研究中继续提问、重命名、置顶或删除。

本地版沿用 SparkFlow 的 Vibe-Trading 服务。首次使用先构建前端，再运行 `npm run research:setup --prefix assistant`。需要 Node 24 和 Python 3.11+。在项目根目录将初始密码通过标准输入传给 `node app/scripts/init-access.mjs <DeepSeek配置文件路径>`。配置文件前三行分别为密钥、官方地址和模型。然后运行 `node app/scripts/serve.mjs`。

网页版点击右上角「设置」，填写个人 API 密钥、模型名称和兼容 Chat Completions 的 HTTPS 地址。服务需允许浏览器跨域请求。配置加密保存于当前浏览器的 IndexedDB，模型请求从浏览器直达所填服务。新设备或新浏览器配置文件需单独填写，也可以在设置中移除密钥。

## 使用

需要 Node.js 18+ 和 curl。

```bash
# 更新行情数据并重新打包页面（约 1–2 分钟）
node app/scripts/update.mjs

# 只用已下载的数据重新打包
node app/scripts/update.mjs --skip-fetch

# 更新后只提交数据和页面并推送到 GitHub（每日定时任务使用）
node app/scripts/update.mjs --git

# 本地预览，打开 http://localhost:5178
node app/scripts/serve.mjs
```

可选本地服务的账户和加密配置保存在项目的 `.private/access.sqlite`。密码使用带随机盐的 scrypt，模型配置使用 AES-256-GCM。主密钥单独存于用户配置目录的 `DynamicRebalancing/keys/vault.key`。迁移设备时需通过安全渠道备份二者。

在本地登录后通过「设置」更换模型或密钥。已在运行的本地研究引擎在下一次启动时加载新配置。

## 自动更新

定时更新在专用的私有仓库 `XiaoyeCodes/Index-Rebalancer-Automation` 中运行：每小时第 23 分钟检查。出现新的美股已收盘交易日，或上次成功校验超过 20 小时才下载和发布；其他检查直接跳过。这样可以在 GitHub 定时任务延迟或一次失败后继续补跑。休市时保留最近交易日，成功校验另有时间戳。私有调度不适用 GitHub 当前对公开仓库定时任务的「60 天不活跃停用」规则。

更新命令 `node app/scripts/update.mjs --git` 下载 Yahoo 日线、剔除未收盘数据、逐个检查行情与汇率日期。A 股 / 港股空日线仅在腾讯与东方财富同日 OHLC 一致后补齐，保留可重放证据。37 个标的最近三个交易日收盘价与第二来源核对；26 个美股标的还对照 Nasdaq 可得约十年历史。已逐条复核的17条差异保存在 `app/data/history-resolutions.json`：9条修正主源价格、8条保留多来源支持的主源价格；原始差异不会删除。每日下载后重新应用已验证修正，适配后续拆股。仅允许精确的标的、日期和已核实数值；任何新增或变化后无法解释的日线差异都会阻止发布。详见[逐条核实报告](docs/historical-discrepancies-2026-11-12.md)。按现金分红事件重建53个原始代码的复权因子，允许0.001%的数值误差；这项检查不代表独立核实所有分红事件的完整性。独立Python实现复算37个标的统计及16组组合回测，成功后才提交行情、校验记录与页面。任一关键校验失败均不发布；打包失败会回滚生成文件。部署使用仅授权本仓库的SSH密钥，私钥保存在私有调度仓库Secret中。

本仓库的 [手动更新工作流](.github/workflows/weekly-update.yml) 保留手动入口。GitHub 可能延迟甚至丢弃定时任务，不能承诺固定分钟发布。小时检查预计每 30 天约需 720 个私有任务计费分钟，另加实际更新耗时，使用账户现有 Actions 额度，不使用付费规格运行器。额度耗尽、密钥撤销或行情源故障会影响更新。网站以 NYSE 日历判断最新应有交易日，数据落后或校验逾期会显示黄色提醒；已打开的页面每 15 分钟及恢复焦点时检查新版，显示刷新入口。

公网 [data-status.json](https://xiaoyecodes.github.io/Index-Rebalancer/data-status.json) 提供最近校验时间、各标的与汇率日期、行情和加密页面的 SHA-256，可验证 Git 提交与公网文件一致。行情日期代表完整收盘快照，不代表实时行情。

## 数据说明

- 价格来自 Yahoo Finance 日线（价格指数不含分红），按交易所当地日期合成为周线；只使用已结束的日线，并统一截到美股快照日期。保留每个标的的实际日期。汇率使用已结束的 UTC 日线。最新周可包含截至快照日的部分交易日。
- 成立较晚的标的，早年用同指数或同类资产接续（如 QQQM 之前用 QQQ，中证 A500 之前用沪深 300 ETF 和上证指数），每个标的的接续来源在页面"数据说明"中注明。
